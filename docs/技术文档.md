# WebAssembly 图像处理应用技术文档

## 1. 项目概述

基于 React 18 + TypeScript + WebAssembly + Web Worker 技术构建的高性能在线图像编辑器，提供接近原生应用的处理速度和流畅的用户体验。项目通过将 OpenCV.js（CDN 加载的预编译 WebAssembly）与自定义 Web Worker 集成，实现了混合引擎的图像处理管道（JavaScript + WebAssembly），并通过 OffscreenCanvas 技术确保 UI 的持续响应性。

### 1.1 项目特色

- **混合处理引擎**：智能选择 JavaScript 或 WebAssembly 引擎，简单滤镜使用 JS，复杂算法使用 WASM
- **TypeScript 支持**：完整的类型安全和开发体验
- **模块化状态管理**：基于 Zustand 的四个独立 store（editorStore、imageStore、collageStore、uiStore）
- **完整的测试体系**：单元测试 + 集成测试，当前覆盖率 20.8%，目标 50%+
- **性能监控系统**：内置性能计时器，实时监控图像处理性能
- **拼贴模式**：独立的图像拼贴功能，支持多种布局和样式设置

### 3.2 状态管理架构

项目采用 Zustand 实现模块化状态管理，分为四个核心 store：

1. **imageStore**：图像数据和历史记录管理
   - 当前图像、原始图像状态
   - 历史记录管理（undo/redo）
   - 图像尺寸和文件信息

2. **editorStore**：编辑器状态和工具管理
   - Worker 和 OpenCV 状态
   - 当前激活工具和参数
   - 裁剪模式和拼贴模式状态
   - 视图控制（缩放、平移）

3. **uiStore**：UI 状态和用户交互管理
   - 加载状态和通知系统
   - 导出面板状态
   - 设备信息和特性支持检测
   - 暗色模式支持

4. **collageStore**：图像拼贴功能专用状态
   - 拼贴图像列表管理
   - 布局和样式配置
   - 画布状态和预览数据

### 3.3 数据流与核心交互

1. **应用初始化**：
   - React 应用启动，初始化 Ant Design ConfigProvider
   - 创建 Web Worker 实例（通过 Vite 内联加载）
   - Worker 异步加载 OpenCV.js (从 CDN)
   - Canvas 控制权转移到 OffscreenCanvas

2. **图像加载流程**：
   - 用户通过文件选择器上传图像
   - 主线程使用临时 Canvas 提取 ImageData
   - 发送到 Worker 进行首次渲染
   - 保存到历史记录管理器

3. **图像处理流程**：
   - 用户选择滤镜或调整参数
   - 根据操作类型智能选择处理引擎：
     - **纯 JavaScript 引擎**：sepia（复古）、grayscale（灰度）、brightness（亮度）、contrast（对比度）、watermark（水印）
     - **WebAssembly 引擎**：blur（模糊）、sharpen（锐化）、crop（裁剪）、rotate（旋转）、flip（翻转）、faceBeauty（人脸美颜）
     - **降级处理**：当 OpenCV 未就绪时，支持 JavaScript 降级处理
   - Worker 内置性能监控，记录每个处理步骤的耗时
   - 处理完成后在 OffscreenCanvas 渲染结果
   - 将处理结果和性能数据传回主线程，更新历史记录

4. **组件懒加载**：
   - 使用 React.lazy() 对非核心组件进行代码分割
   - ParamsPanel、ExportPanel、CollageMode 采用懒加载策略

## 4. 核心技术实现

### 4.1 Web Worker 集成

```typescript
// App.tsx - Worker 初始化（TypeScript 版本）
useEffect(() => {
  // Vite TypeScript Worker 加载
  const worker = new Worker(
    new URL('./utils/imageWorker.ts?worker', import.meta.url)
  );
  setImageWorker(worker);
  setCanvasInitialized(false); // 重置Canvas初始化状态

  worker.onmessage = (e: MessageEvent) => {
    const { type } = e.data;

    if (type === 'opencv-loaded') {
      useEditorStore.getState().setOpenCVLoaded(true);
    } else if (type === 'worker-ready') {
      useEditorStore.getState().setWorkerReady(true);
    }

    handleWorkerMessage(e);
  };

  return () => worker.terminate();
}, [handleWorkerMessage, setImageWorker, setCanvasInitialized]);
```

### 4.2 OpenCV.js 动态加载

```typescript
// imageWorker.ts - OpenCV 加载（TypeScript 版本）
// 初始化Module - 按照技术文档方案
(self as any).Module = {
  noInitialRun: true,
  onRuntimeInitialized: () => {
    self.postMessage({ type: 'opencv-loaded' });
  },
};

// 异步加载OpenCV
(async () => {
  try {
    const response = await fetch(
      'https://wasm-worker.oss-cn-nanjing.aliyuncs.com/opencv.wasm'
    );
    if (!response.ok) {
      throw new Error(
        `加载 wasm 失败： ${response.status} ${response.statusText}`
      );
    }
    const buffer = await response.arrayBuffer();
    (self as any).Module.wasmBinary = buffer;
    self.importScripts(
      'https://wasm-worker.oss-cn-nanjing.aliyuncs.com/opencv.js'
    );
  } catch (error) {
    console.error('在 worker 中加载 OpenCV 失败:', error);
    self.postMessage({ type: 'error', payload: '初始化 OpenCV 失败。' });
  }
})();
```

    this.operationName = operationName;
    this.steps = [];

  }

  step(stepName) {

class MemoryManager {
  private cache = new Map();
  private maxSize = 100 * 1024 * 1024; // 100MB
  private currentSize = 0;

  set(key: string, data: ImageData): void {
    const size = data.data.byteLength;

    // LRU 清理
    while (this.currentSize + size > this.maxSize && this.cache.size > 0) {
      const firstKey = this.cache.keys().next().value;
      const firstData = this.cache.get(firstKey);
      this.currentSize -= firstData.data.byteLength;
      this.cache.delete(firstKey);
    }

    this.cache.set(key, data);
    this.currentSize += size;
  }

  // WeakRef 支持
  private weakCache = new WeakMap();

}

### 15.4 工具链协作关系

#### 15.4.1 TSC 与 ESLint 的分工

**TSC 负责**：

- 类型系统验证
- 编译时错误检查
- 模块解析验证
- TypeScript 语法检查

**ESLint 负责**：

- 代码质量规范
- 最佳实践检查
- 风格一致性
- 运行时逻辑问题检测

**协作优势**：

- TSC 确保类型安全，ESLint 确保代码质量
- TSC 在编译层面检查，ESLint 在语法树层面分析
- 两者结合提供全方位的代码检查

#### 15.4.2 检查优先级

1. **TypeScript 类型检查**（最高优先级）
   - 类型错误会导致编译失败
   - 必须首先通过类型检查

2. **ESLint 代码质量检查**
   - 可自动修复的问题会被自动处理
   - 无法修复的错误会阻止提交

3. **Prettier 格式化**
   - 自动应用，不会失败
   - 确保代码格式一致性

4. **相关测试执行**
   - 验证修改是否破坏现有功能
   - 仅运行与修改相关的测试

### 15.5 错误处理和恢复机制

#### 15.5.1 自动恢复

当检查失败时，`lint-staged` 会：

1. 备份原始状态到 Git stash
2. 尝试执行所有检查步骤
3. 如果任何步骤失败，自动恢复到原始状态
4. 清理临时文件

#### 15.5.2 常见错误类型

**TypeScript 错误**：

```typescript
// 类型不匹配
Property 'foo' does not exist on type 'Bar'

// 缺少类型注解
Parameter 'event' implicitly has an 'any' type
```

**ESLint 错误**：

```javascript
// 使用 any 类型
warning: Unexpected any. Specify a different type @typescript-eslint/no-explicit-any

// 不安全的 Function 类型
error: The `Function` type accepts any function-like value @typescript-eslint/no-unsafe-function-type
```

### 15.7 最佳实践建议

#### 15.7.1 开发流程

1. **编写代码时**：
