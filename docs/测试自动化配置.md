# 测试自动化配置指南

## 概述

本项目配置了完整的测试自动化流程，确保每次代码提交和推送时都能保证代码质量。

## 自动化测试流程

### 1. Pre-commit 钩子（提交前）

当你运行 `git commit` 时，会自动执行：

```bash
# 类型检查
pnpm type-check

# 对修改的文件进行：
# - ESLint 检查和自动修复
# - Prettier 格式化
# - 运行相关的测试
npx lint-staged
```

**触发条件**：每次 `git commit`
**检查范围**：仅检查修改的文件
**失败处理**：阻止提交，需要修复问题后重新提交

### 2. Pre-push 钩子（推送前）

当你运行 `git push` 时，会自动执行：

```bash
# 运行完整测试套件
pnpm test:run

# 生成测试覆盖率报告
pnpm test:coverage
```

**触发条件**：每次 `git push`
**检查范围**：整个项目的所有测试
**失败处理**：阻止推送，需要修复问题后重新推送

### 3. CI/CD 流水线（GitHub Actions）

当代码推送到 GitHub 时，会自动执行：

- 多个 Node.js 版本的兼容性测试
- 完整的类型检查
- 代码风格检查
- 全量测试执行
- 测试覆盖率上传

## 测试覆盖率要求

项目设置了以下测试覆盖率阈值：

- **分支覆盖率**: ≥ 70%
- **函数覆盖率**: ≥ 80%
- **行覆盖率**: ≥ 80%
- **语句覆盖率**: ≥ 80%

如果覆盖率低于阈值，测试将失败。

## 常用命令

### 开发阶段

```bash
# 启动测试监听模式（文件变化时自动运行测试）
pnpm test:watch

# 运行所有测试
pnpm test

# 运行测试并生成覆盖率报告
pnpm test:coverage

# 只运行与修改文件相关的测试
pnpm test:changed

# 启动测试 UI 界面
pnpm test:ui
```

### CI/CD 环境

```bash
# 运行 CI 测试（包含覆盖率和详细报告）
pnpm test:ci

# 类型检查
pnpm type-check

# 代码风格检查
pnpm lint
```

## 跳过钩子（紧急情况）

在紧急情况下，可以跳过 Git 钩子：

```bash
# 跳过 pre-commit 钩子
git commit --no-verify -m "emergency fix"

# 跳过 pre-push 钩子
git push --no-verify
```

**⚠️ 警告**：只在紧急情况下使用，跳过钩子可能会引入问题。

## 故障排除

### 1. Pre-commit 钩子失败

```bash
# 查看详细错误信息
git commit -v

# 手动运行 lint-staged 查看问题
npx lint-staged

# 修复后重新提交
git add .
git commit -m "fix issues"
```

### 2. 测试失败

```bash
# 运行单个测试文件
pnpm test src/utils/__tests__/historyManager.test.ts

# 运行特定测试用例
pnpm test --grep "应该能够添加新的历史记录"

# 查看测试覆盖率详情
pnpm test:coverage
# 然后打开 coverage/index.html
```

### 3. 类型检查失败

```bash
# 运行类型检查
pnpm type-check

# 查看 TypeScript 错误
npx tsc --noEmit --pretty
```

## 最佳实践

### 1. 提交前准备

```bash
# 运行完整检查
pnpm type-check && pnpm lint && pnpm test:run

# 或者直接提交，让钩子自动检查
git add .
git commit -m "feat: add new feature"
```

### 2. 编写测试

- 为新功能编写测试
- 确保测试覆盖率满足要求
- 运行 `pnpm test:watch` 进行测试驱动开发

### 3. 修复问题

- 优先修复失败的测试
- 检查类型错误
- 确保代码风格一致

## 配置文件说明

- `.husky/pre-commit`: Pre-commit 钩子配置
- `.husky/pre-push`: Pre-push 钩子配置
- `.github/workflows/ci.yml`: GitHub Actions 配置
- `vitest.config.ts`: 测试框架配置
- `package.json` 中的 `lint-staged`: 暂存文件处理配置

## 团队协作

所有团队成员都应该：

1. 安装项目依赖后运行 `pnpm prepare` 激活 Git 钩子
2. 遵循测试覆盖率要求
3. 不跳过 Git 钩子（除非紧急情况）
4. 及时修复 CI 失败的问题

这样可以确保主分支始终保持高质量的代码状态。
