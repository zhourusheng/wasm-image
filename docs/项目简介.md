## 项目简介

基于 React 18 + TypeScript 的浏览器端 Wasm 图像编辑器。通过 Web Worker + OffscreenCanvas + OpenCV.js（WebAssembly）将图像处理从主线程解耦，支持亮度/对比度/饱和度/模糊/边缘检测/阈值/锐化/复古/图像增强、裁剪/旋转/翻转、水印（文字/图片）、AI 美颜、人像背景去除、拼贴合成等功能。使用 Zustand 组织编辑状态与历史（撤销/重做），以参数面板 + 预览/应用两阶段交互避免卡顿，配合导出面板实现格式/质量/尺寸预估与一键下载。内置性能埋点与降级方案，保证在不同设备与网络环境下都能稳定运行。

- 技术栈: React 18, TypeScript, Vite, Tailwind CSS, Ant Design, Zustand, Web Worker, OffscreenCanvas, OpenCV.js (WASM), createImageBitmap, Vitest + Testing Library, ESLint/Prettier/Husky/lint-staged
- 代表模块: `src/utils/imageWorker.ts`（WASM/Worker 流水线）、`src/hooks/useImageProcessing.ts`（编辑指令编排/消息处理）、`src/utils/historyManager.ts`（撤销重做）、`src/components/layout/*`（Canvas/Toolbar/Params/Export/Collage）、`src/store/*`（editor/image/ui/collage）
- 性能与体验: 主线程仅负责交互与调度；图像绘制转移至 Worker 的 OffscreenCanvas；参数拖动实时预览、点击“应用”才入历史；`PerformanceTimer` 分步记录耗时；懒加载参数面板/导出/拼贴模块降低首屏体积。

## 主要工作

### 架构与性能治理

- 设计 Worker + OffscreenCanvas + OpenCV.js 的处理流水线，将渲染和计算解耦，避免主线程阻塞；按操作类型在 JS 与 Wasm 之间动态取舍（如灰度/复古用纯 JS，Canny/CLAHE/GrabCut 用 OpenCV.js）。
- 引入 `PerformanceTimer` 与 `logPerformanceToConsole`，对“解码→计算→绘制”全链路分步计时，定位瓶颈并指导优化。
- 首屏按路由/功能懒加载：`ParamsPanel`、`ExportPanel`、`CollageMode` 通过 `React.lazy` 拆分，减少初始包体。

### 图像编辑引擎与降级策略

- 在 `imageWorker.ts` 实现高频操作（裁剪/旋转/翻转/亮度/对比度/饱和度/模糊/阈值/边缘/锐化/复古/增强/水印/压缩预览/背景去除/AI 美颜）。
- 关键难点与解决：
  - OpenCV.js 按“wasmBinary + importScripts”异步加载，定义 `Module.onRuntimeInitialized` 与 `opencv-loaded`/`worker-ready` 双就绪态；`App.tsx` 处理握手，`Canvas.tsx` 再转移控制权，保证单次转移与幂等。
  - 严格的内存管理：所有 `cv.Mat`/`MatVector`/内核在 try/finally 内显式 `delete()`，防止长会话泄漏。
  - `toStandardImageData` 处理 SharedArrayBuffer 存在与否，确保 worker/主线程间数据可安全传递。
  - 预览与应用分流：`processEdit(op, params, isPreview)` 预览不入历史，应用才 `updateImage`；结合 `lastProcessedImageId` 避免重复渲染。
  - AI 美颜人像区域采用 OpenCV 估算 + 羽化蒙版融合，失败时回退纯 JS 模糊/提亮，保证结果稳定、边缘自然。

### 高可用历史系统与编辑体验

- 设计 `HistoryManager`：深拷贝入栈、Redo/Undo 有界历史、索引跳转；在 `imageStore` 统一对接 `setImage`/`updateImage`/`undo`/`redo`/`revertToOriginal`，并在 `Canvas` 中以 worker 的 `original` 指令“只渲染不入栈”保障一致性。
- 裁剪交互：`useCanvas` 维护“创建/移动”两种拖拽模式，按缩放转换坐标并在覆盖层 `cropCanvas` 实时描绘，`Canvas` 负责同步尺寸与高亮矩形。

### 拼贴合成与导出管线

- 拼贴模式：`imageCollageUtils` 支持竖/横/网格布局，支持间距/列数/背景色与预览；“应用”会生成临时画布→Blob→ImageData→进入编辑主流程。
- 导出面板：`generateExportPreview` 使用 `createImageBitmap` + 尺寸缩放 + `compressCanvasImage`（JPEG/PNG/WebP）生成预估大小与预览图，关闭时 `URL.revokeObjectURL` 做资源回收。

### 状态管理与可维护性

- 使用 Zustand 拆分 `editorStore`/`imageStore`/`uiStore`/`collageStore`，保证处理态/工具态/UI 态分离；`useZoom` 用 `ResizeObserver` 自适应“适屏缩放”并与用户手动缩放状态解耦。
- 封装 `notificationService` 与 AntD `App` 实例解耦，支持统一的确认/消息/通知体验。
- 严格类型：所有公开 API 有显式类型；对 Worker 消息载荷/图像数据/导出参数定义统一类型于 `types/index.ts`。

### 质量保障与工程基建

- 测试：Vitest + Testing Library 覆盖 Canvas 集成、useImageProcessing 集成、EditorStore 单测；在 `test/setup.ts` 全量 mock OffscreenCanvas/Worker/ImageData，保障在 JSDOM 下可执行。
- 代码规范：ESLint + Prettier + Husky + lint-staged；提交前 `type-check`/`lint`/`vitest related` 快速回归；提供 `test:ci`/`test:coverage` 便于流水线集成。
- DX：Vite 本地开发，Tailwind 原子化样式，AntD 组件快速搭建面板；`vite` + `terser`/可选 `visualizer` 分析构建。

### 面向面试可深入的点

- 导出预览的高性能实现与资源回收、Blob URL 生命周期。
- 可靠的降级策略（JS vs Wasm）与异常兜底（通知系统 + 恢复 UI 状态）。
