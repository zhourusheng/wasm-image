# WebAssembly 图像处理应用技术文档

## 1. 项目概述

基于 WebAssembly 和 Web Worker 技术构建的高性能在线图像编辑器，提供接近原生应用的处理速度和流畅的用户体验。本项目通过将 C/C++ 编写的图像处理算法（或利用如 OpenCV.js 的预编译库）编译为 WebAssembly，结合 Web Worker 实现多线程处理，大幅提升图像处理性能。

## 2. 技术栈选型

### 2.1 基础技术栈
- **包管理器**：pnpm（禁止使用 npm 或 yarn）
- **前端框架**：React
- **CSS 框架**：Tailwind CSS
- **图像处理核心**：WebAssembly + OpenCV.js
- **并行处理**：Web Worker
- **渲染优化**：OffscreenCanvas
- **任务调度**：`requestIdleCallback`

### 2.2 技术选型理由

- **pnpm**：相比 npm 和 yarn，具有更快的安装速度和更高效的磁盘空间利用率。
- **React**：组件化开发，虚拟 DOM 高效渲染，适合构建复杂的交互界面。
- **Tailwind CSS**：提供原子化 CSS 类，加快 UI 开发速度，减少自定义 CSS 的需求。
- **WebAssembly (OpenCV.js)**：提供接近原生的执行速度，特别适合图像处理等计算密集型任务。
- **Web Worker**：在独立线程中执行耗时操作，避免主线程阻塞，保持 UI 响应流畅。
- **OffscreenCanvas**：允许在 Worker 线程中直接进行 Canvas 渲染，避免了主线程和 Worker 线程之间大量图像数据的频繁复制，是性能优化的关键。
- **requestIdleCallback**：在浏览器空闲时执行低优先级任务，提升用户体验。

### 3.2 数据流与核心交互

1.  **初始化**：React 组件首次挂载时，主线程通过 `canvas.transferControlToOffscreen()` 获取主 Canvas 的控制权，并将其作为 `Transferable` 对象发送给 Web Worker。**此操作只能执行一次**。
2.  **用户上传图片**：主线程加载图片，使用一个临时的内存 Canvas 将其转换为 `ImageData`，然后将 `ImageData` 发送给 Worker 进行首次渲染。
3.  **用户编辑操作**：用户点击滤镜或裁剪按钮，主线程从 `HistoryManager` 获取当前最新的 `ImageData`，连同操作指令一起发送给 Worker。
4.  **后台处理**：
    -   `imageWorker.js` 接收任务。
    -   调用 `wasmBridge.js` 中的图像处理函数。
    -   `wasmBridge.js` 使用 `OpenCV.js` 对 `ImageData` 进行处理。
5.  **后台渲染**：处理完成后，`wasmBridge.js` 直接在 `OffscreenCanvas` 上渲染结果。用户可以立即看到视觉变化。
6.  **状态同步（关键妥协）**：为了让主线程的 `HistoryManager` 能够管理撤销/重做，Worker 在渲染完成后，**必须将生成的 `ImageData` 对象作为 `Transferable` 对象传回主线程**。主线程接收到后，将其存入历史记录栈。
7.  **撤销/重做**：用户点击撤销/重做时，主线程从 `HistoryManager` 中取出对应状态的 `ImageData`，并将其发送给 Worker 重新渲染。

## 4. 核心技术实现

### 4.1 WebAssembly 桥接层

我们创建了 `src/wasm/wasmBridge.js` 文件，作为 Worker 与 OpenCV.js 功能之间的桥梁。它负责封装所有 OpenCV 操作，使其易于在 Worker 中调用。

```javascript
// wasmBridge.js - 示例
// 该文件在 Worker 中通过 importScripts() 导入

// 函数被附加到 self，使其在 Worker 全局可用
self.wasmProcessImage = async function(imageData, op, params, ctx) {
  await self.wasmInit(); // 初始化 OpenCV
  
  const src = self.cv.matFromImageData(imageData);
  let dst;

  // ... 根据 op 执行不同的 OpenCV 操作 ...
  switch (op) {
    case 'crop':
      const rect = new self.cv.Rect(params.x, params.y, params.width, params.height);
      const roi = src.roi(rect);
      dst = new self.cv.Mat();
      // 关键：必须使用 copyTo() 复制 ROI，否则会得到错误引用
      roi.copyTo(dst);
      roi.delete();
      break;
    // ... 其他 case ...
  }
  
  // 渲染到 OffscreenCanvas
  const resultImageData = ctx.createImageData(dst.cols, dst.rows);
  resultImageData.data.set(new Uint8ClampedArray(dst.data));
  ctx.putImageData(resultImageData, 0, 0);

  // 返回 ImageData 用于历史记录
  return resultImageData;
};
```

### 4.2 Web Worker 实现

`src/workers/imageWorker.js` 是后台处理的核心。它负责加载 OpenCV.js，管理与主线程的通信，并调用 Wasm 桥接层。

```javascript
// src/workers/imageWorker.js 简化示例

importScripts('/src/wasm/wasmBridge.js'); // 导入桥接层

let offscreenCanvas = null;
let ctx = null;

// ... OpenCV.js 加载逻辑 ...

self.onmessage = async (e) => {
    const { type, payload } = e.data;

    switch (type) {
        case 'init':
            // 接收来自主线程的 OffscreenCanvas
            offscreenCanvas = payload.canvas;
            ctx = offscreenCanvas.getContext('2d');
            postMessage({ type: 'worker-ready' });
            break;

        case 'image-process':
            if (self.cv && ctx) {
                // 调用 Wasm 桥接函数处理图像
                const resultImageData = await self.wasmProcessImage(
                    payload.imageData, payload.action, payload.params, ctx
                );
                // 将结果作为 Transferable 对象传回主线程用于历史记录
                postMessage(
                    { type: 'image-processed', payload: { imageData: resultImageData } },
                    [resultImageData.data.buffer]
                );
            }
            break;
    }
};
```

### 4.3 OffscreenCanvas 与主线程集成

在主线程的 React 组件 (`App.jsx`) 中，通过 `useEffect`钩子管理 Worker 和 `OffscreenCanvas` 的生命周期是至关重要的。

```javascript
// App.jsx - 简化示例

function App() {
  const canvasRef = useRef(null);
  const imageWorker = useRef(null);
  
  // 主 effect，用于 Worker 初始化，仅运行一次
  useEffect(() => {
    const worker = new Worker(new URL('./workers/imageWorker.js', import.meta.url));
    imageWorker.current = worker;
    
    worker.onmessage = (e) => {
      const { type, payload } = e.data;
      switch (type) {
        case 'opencv-loaded':
          if (canvasRef.current) {
            // 关键：transferControlToOffscreen() 只能调用一次！
            const offscreen = canvasRef.current.transferControlToOffscreen();
            worker.postMessage({ type: 'init', payload: { canvas: offscreen } }, [offscreen]);
          }
          break;
        case 'image-processed':
          // 接收 worker 返回的 imageData，用于更新历史记录
          if (payload.imageData) {
            historyManager.add(payload.imageData);
          }
          setLoading(false);
          break;
        // ... 其他 case ...
      }
    };
    
    return () => worker.terminate();
  }, []); // 空依赖数组确保此 effect 仅在挂载时运行一次

  // ...
}
```

### 4.4 交互式 UI 的挑战与解决方案 (裁剪功能)

**挑战**：一旦 Canvas 控制权被转移，主线程就无法再调用 `getContext()`，这意味着所有依赖它的交互式 UI（如绘制裁剪框）都会失效。

**解决方案**：使用一个独立的、绝对定位的**覆盖层 Canvas** (`overlayCanvas`)。
1.  **结构**：在主 Canvas 上方叠加一个透明的 `overlayCanvas`。
2.  **交互**：所有鼠标事件（按下、移动、抬起）都绑定到 `overlayCanvas` 上。
3.  **绘制**：进入裁剪模式时，获取当前图像状态，并将其绘制到 `overlayCanvas` 上。所有预览效果（如半透明蒙版、裁剪框）也都在 `overlayCanvas` 上绘制。
4.  **同步**：为防止视觉跳动，进入裁剪模式时，必须用 JS 获取主 Canvas 的 `getBoundingClientRect()`，并将得到的尺寸和位置应用到 `overlayCanvas` 的 CSS 样式上，确保两者完美重合。
5.  **执行**：用户确认裁剪后，仅将裁剪参数（x, y, width, height）发送给 Worker，由 Worker 在后台的 `OffscreenCanvas` 上执行真正的裁剪操作。

这个方案将交互层与渲染层完全分离，解决了 `OffscreenCanvas` 模式下的 UI 交互难题。

### 5.5 使用 `requestIdleCallback` 优化数据同步

**挑战**：在我们的架构中，Worker 线程在完成图像处理并在 `OffscreenCanvas` 上渲染后，需要将结果 `ImageData` 传回主线程以更新历史记录。这个数据传输（尤其是对于高分辨率图像）可能非常耗时。如果这个操作在用户正在进行其他交互（如快速切换滤镜、拖动滑块）时立即执行，可能会阻塞主线程或造成事件循环拥堵，导致界面卡顿。

**解决方案**：`requestIdleCallback` API 允许我们在浏览器的空闲时段执行后台和低优先级工作，而不会影响延迟关键事件，如动画和输入响应。我们可以利用它将非紧急的数据同步任务推迟到浏览器空闲时执行。

**实现**：
-   **影响文件**：`src/workers/imageWorker.js`
-   **改动复杂度**：低。只需在 `postMessage` 调用外包裹一层 `requestIdleCallback`。

**核心思路**：
1.  **即时渲染**：Worker 处理完图像后，立即在 `OffscreenCanvas` 上渲染结果。用户可以马上看到视觉变化，这是高优先级任务。
2.  **延迟同步**：将处理结果 `ImageData` 发送回主线程以供 `HistoryManager` 使用，这是一个可以稍后执行的低优先级任务。

**代码示例 (`src/workers/imageWorker.js`)**：

```javascript
// ... 在 imageWorker.js 的 onmessage 处理函数中

case 'image-process':
    if (self.cv && ctx) {
        // 1. 图像处理和渲染照常进行，保证即时视觉反馈
        const resultImageData = await self.wasmProcessImage(
            payload.imageData, payload.action, payload.params, ctx
        );
        
        // 2. 使用 requestIdleCallback 调度数据同步任务
        if ('requestIdleCallback' in self) {
            requestIdleCallback(() => {
                // 当浏览器空闲时，才将结果传回主线程用于历史记录
                postMessage(
                    { type: 'image-processed', payload: { imageData: resultImageData } },
                    [resultImageData.data.buffer]
                );
            });
        } else {
            // 为不支持该 API 的浏览器提供回退
            postMessage(
                { type: 'image-processed', payload: { imageData: resultImageData } },
                [resultImageData.data.buffer]
            );
        }
    }
    break;
```

**收益**：通过这种方式，我们将**即时视觉反馈**（在 `OffscreenCanvas` 上渲染）与**后台状态同步**（更新历史记录）解耦。即使用户连续快速地应用多个滤镜，UI 也能保持流畅，因为繁重的数据传输被智能地安排在了交互的间隙。这极大地提升了复杂操作下的用户体验，同时代码改动极小。

### 6.4 撤销/重做功能

```javascript
class HistoryManager {
  constructor(maxHistory = 20) {
    this.undoStack = [];
    this.redoStack = [];
    this.maxHistory = maxHistory;
  }
  
  // 添加状态到历史
  addState(imageData) {
    // 克隆图像数据
    const clonedData = new ImageData(
      new Uint8ClampedArray(imageData.data),
      imageData.width,
      imageData.height
    );
    
    this.undoStack.push(clonedData);
    
    // 清空重做栈
    this.redoStack = [];
    
    // 限制历史长度
    if (this.undoStack.length > this.maxHistory) {
      this.undoStack.shift();
    }
  }
  
  // 撤销操作
  undo() {
    if (this.undoStack.length <= 1) return null;
    
    // 保存当前状态到重做栈
    const current = this.undoStack.pop();
    this.redoStack.push(current);
    
    // 返回上一个状态
    return this.undoStack[this.undoStack.length - 1];
  }
  
  // 重做操作
  redo() {
    if (this.redoStack.length === 0) return null;
    
    // 获取重做状态
    const state = this.redoStack.pop();
    this.undoStack.push(state);
    
    return state;
  }
}
```

### 7.2 已解决的关键问题

在 `OffscreenCanvas` 的集成过程中，我们遇到并解决了一系列关键问题，这些是文档化非常有价值的实践经验：

1.  **错误：`Cannot transfer control from a canvas for more than one time.`**
    -   **原因**：在 React 的 `useEffect` 中，如果依赖项变化导致 effect 重复执行，会多次尝试转移同一个 canvas 的控制权。
    -   **解决方案**：将 Worker 初始化和 `transferControlToOffscreen()` 调用放在一个具有**空依赖数组 (`[]`)** 的 `useEffect` 中，确保它在组件生命周期中只执行一次。

2.  **错误：`Cannot resize canvas after call to transferControlToOffscreen().`**
    -   **原因**：主线程在转移控制权后，无权再修改 Canvas 的 `width` 或 `height` 属性。
    -   **解决方案**：当需要从 `HTMLImageElement` 获取 `ImageData` 时，应在内存中创建一个临时的、全新的 canvas 来执行此操作，而不是使用页面上已被接管的 canvas。

3.  **错误：`Cannot get context from a canvas that has transferred its control to offscreen.`**
    -   **原因**：与上一条类似，主线程无权访问 `getContext()`。
    -   **解决方案**：这是最核心的架构决策点。主线程不能再为了保存历史记录而从 canvas 读取数据。解决方案是让 **Worker 在处理完图像后，将结果 `ImageData` 传回主线程**，主线程仅使用这个返回的数据来更新历史记录。

4.  **错误：`ReferenceError: HTMLCanvasElement is not defined` (在 Worker 中)**
    -   **原因**：`OpenCV.js` 的 `cv.imshow(canvas, mat)` 函数内部会检查 `canvas` 是否为 `HTMLCanvasElement` 的实例，但在 Worker 的全局作用域中不存在这个构造函数。
    -   **解决方案**：绕开 `cv.imshow()`。手动创建 `ImageData` 对象 (`ctx.createImageData()`)，然后用 `mat.data` 填充它，最后通过 `ctx.putImageData()` 将其渲染到 `OffscreenCanvas` 上。

// 性能测试框架
class PerformanceTest {
  constructor() {
    this.results = {};
  }
  
  // 测试特定滤镜性能
  async testFilter(filterName, imageData, iterations = 5) {
    const jsProcessor = new JavaScriptProcessor();
    const wasmProcessor = await getWasmProcessor();
    
    // 预热
    await jsProcessor.applyFilter(imageData, filterName);
    await wasmProcessor.applyFilter(imageData, filterName);
    
    // 测试 JavaScript 版本
    const jsResults = [];
    for (let i = 0; i < iterations; i++) {
      const start = performance.now();
      await jsProcessor.applyFilter(imageData, filterName);
      jsResults.push(performance.now() - start);
    }
    
    // 测试 WebAssembly 版本
    const wasmResults = [];
    for (let i = 0; i < iterations; i++) {
      const start = performance.now();
      await wasmProcessor.applyFilter(imageData, filterName);
      wasmResults.push(performance.now() - start);
    }
    
    // 计算平均值
    const jsAvg = jsResults.reduce((a, b) => a + b, 0) / iterations;
    const wasmAvg = wasmResults.reduce((a, b) => a + b, 0) / iterations;
    
    this.results[filterName] = {
      js: jsAvg,
      wasm: wasmAvg,
      improvement: jsAvg / wasmAvg
    };
    
    return this.results[filterName];
  }
  
  // 生成报告
  generateReport() {
    console.table(this.results);
  }
}
